On Windows, VS Code stores user-level configuration files in the roaming profile directory:

```text
%APPDATA%\Code\User
```

For a typical account, this expands to:

```text
C:\Users\<username>\AppData\Roaming\Code\User
```

The two files that are commonly needed when configuring VS Code and Model Context Protocol (MCP) servers are:

```text
settings.json
mcp.json
```

Both files are located in the same directory.

## VS Code Settings

The general VS Code user settings file is:

```text
%APPDATA%\Code\User\settings.json
```

You can also open it from VS Code with the **Preferences: Open User Settings (JSON)** command.

## MCP Configuration

The MCP server configuration file is:

```text
%APPDATA%\Code\User\mcp.json
```

This file defines the MCP servers that VS Code can start or connect to. Keep its JSON syntax valid: property names and string values need double quotes, and entries need commas where required.

## Configure `no_proxy` as a List

In a shell or a traditional environment variable, `no_proxy` is often a comma-separated string:

```text
localhost,127.0.0.1,.example.com
```

That representation should not be used for the corresponding VS Code setting. In `settings.json`, configure `no_proxy` as a JSON list instead:

```json
{
	"http.noProxy": [
		"localhost",
		"127.0.0.1",
		".example.com"
	]
}
```

Each host or domain rule is a separate array item. Do not combine multiple rules into one comma-separated string:

```json
{
	"http.noProxy": "localhost,127.0.0.1,.example.com"
}
```

Using the array form lets VS Code interpret every exclusion independently and prevents local services or MCP endpoints from being sent through the configured proxy.

## Quick Checklist

- Edit `%APPDATA%\Code\User\settings.json` for VS Code user settings.
- Edit `%APPDATA%\Code\User\mcp.json` for MCP server definitions.
- Use a JSON array for `http.noProxy` entries.
- Put one hostname, IP address, or domain suffix in each array item.
