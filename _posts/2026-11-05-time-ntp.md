## 快速查看当前状态

```bash
timedatectl status
```

关键字段：
- **System clock synchronized** — 是否已同步
- **NTP service** — NTP 守护进程是否在运行
- **RTC in local TZ** — 应为 `no`（RTC 存 UTC，推荐）

## 方式一：chronyd（现代默认，推荐）

RHEL/CentOS 7+、Fedora、SUSE、Ubuntu 18.04+ 默认使用 `chrony`。

### 安装与启用

```bash
# RHEL/CentOS/Rocky/Fedora
sudo dnf install chrony
sudo systemctl enable --now chronyd

# Debian/Ubuntu
sudo apt install chrony
sudo systemctl enable --now chrony
```

### 配置 NTP 源

编辑 `/etc/chrony.conf`（Debian/Ubuntu 为 `/etc/chrony/chrony.conf`）：

```bash
# NTP 服务器（可配多个，chrony 会自动选最优）
server ntp.aliyun.com iburst
server cn.pool.ntp.org iburst
server time.windows.com iburst

# 允许 chrony 在大偏差时直接跳变（而非只微调）
makestep 1.0 3

# 启用硬件时间戳（如果网卡支持，提高精度）
# hwtimestamp *

# 允许本地网络的主机同步（可选，做 NTP 服务器时用）
# allow 192.168.1.0/24

# RTC 同步：chrony 会定期将系统时间写入 CMOS/RTC
rtcsync
```

`iburst` = 启动时快速发送 4 个请求，加速初始同步。

### 常用命令

```bash
# 查看同步状态（最常用）
chronyc tracking

# 查看所有 NTP 源的详细信息
chronyc sources -v

# 查看 NTP 源的统计信息（偏移、延迟、抖动）
chronyc sourcestats -v

# 立即强制同步（大偏差时跳变）
sudo chronyc makestep

# 查看 chrony 是否在选择最优源
chronyc activity
```

## 方式二：ntpd（传统 NTP 守护进程）

老系统或特定环境仍使用 `ntp`。

```bash
sudo dnf install ntp     # 或 apt install ntp
sudo systemctl enable --now ntpd
```

配置 `/etc/ntp.conf`：

```bash
server ntp.aliyun.com iburst
server cn.pool.ntp.org iburst
```

```bash
ntpq -p          # 查看 NTP 源状态
sudo ntpdate ntp.aliyun.com   # 一次性手动同步（需先停 ntpd）
```

## 方式三：一次性手动同步（不装守护进程）

```bash
# chrony 方式
sudo chronyd -q 'server ntp.aliyun.com iburst'

# ntpdate 方式（已弃用但仍可用）
sudo ntpdate ntp.aliyun.com
```

## 方式四：systemd-timesyncd（轻量，适合桌面/容器）

```bash
sudo systemctl enable --now systemd-timesyncd
timedatectl set-ntp true

# 配置 NTP 源
# /etc/systemd/timesyncd.conf
[Time]
NTP=ntp.aliyun.com cn.pool.ntp.org
FallbackNTP=time.windows.com 0.pool.ntp.org
```

```bash
# 查看状态
timedatectl timesync-status
timedatectl show-timesync
```

## 同步后写入硬件时钟（CMOS/RTC）

```bash
# 将系统时间写入 RTC（CMOS）
sudo hwclock --systohc

# 将 RTC 设为 UTC（推荐）
sudo timedatectl set-local-rtc no

# 查看硬件时钟
sudo hwclock -r
```

> `chrony` 配置了 `rtcsync` 时会自动定期写入 RTC，无需手动操作。

## 各方式对比

| | chronyd | ntpd | systemd-timesyncd | ntpdate（一次性） |
|---|---|---|---|---|
| **精度** | 高（亚毫秒） | 高 | 中（毫秒） | 低 |
| **资源占用** | 低 | 中 | 极低 | 无（运行即退出） |
| **网络断开** | 仍可用（本地频率估算） | 仍可用 | 停止同步 | N/A |
| **大偏差处理** | `makestep` 快速跳变 | 拒绝同步（panic gate） | 跳变 | 直接跳变 |
| **适用场景** | 服务器/桌面（推荐） | 传统服务器 | 桌面/容器 | 快速校准 |
| **守护进程** | 是 | 是 | 是（systemd 内置） | 否 |

## 常见问题

### 同步不生效

```bash
# 1. 检查防火墙是否放行 UDP 123
sudo firewall-cmd --add-service=ntp --permanent
sudo firewall-cmd --reload

# 2. 检查 NTP 源是否可达
chronyc sources -v
# ^? 表示不可达，^* 表示已同步，^+ 表示备选

# 3. 检查 chrony 是否在运行
systemctl status chronyd

# 4. 检查时间偏差是否过大（> 1000秒 ntpd 会拒绝）
sudo chronyc makestep   # chrony 强制跳变
```

### 容器内同步 NTP

容器通常不运行 NTP 守护进程，依赖宿主机时间。如需容器内独立同步：

```bash
# 方案1：宿主机同步，容器共享内核时钟（默认行为，推荐）
# 宿主机上运行 chronyd 即可

# 方案2：容器内运行 chronyd（需要特定权限）
docker run --cap-add SYS_TIME -d chrony

# 方案3：一次性同步
docker exec <container> chronyd -q 'server ntp.aliyun.com iburst'
```

### 虚拟机时间漂移

```bash
# VMware/KVM: 安装 guest tools 并启用时间同步
# KVM: 确保宿主机加载 kvm-clock
cat /sys/devices/system/clocksource/clocksource0/current_clocksource
# 应为 kvm-clock（虚拟机内）或 tsc（物理机）
```
