为何能一眼区分出AI视频？一眼就能看出来是AI视频，问题主要出在**生成**环节，不在清晰度上。

## 常见的"AI 感"及原因

| 一眼可见的特征 | 根源 |
|---|---|
| 皮肤像蜡像，画面过于光滑干净 | 去噪训练目标偏向"平均值"，加上 VAE 丢掉了噪点和胶片颗粒等高频随机信息 |
| 颜色过饱和、对比度高、像广告片 | CFG（分类器引导）系数调得高，加上训练数据偏好精美的素材视频 |
| 整个画面锐度一致，景深不自然 | 真实镜头有光学特性（焦外、色散、暗角），模型只学到了表面效果 |
| 动作偏慢，像慢镜头，运镜过于平滑 | 训练数据中慢动作和稳定器镜头多；快速运动的生成难度大，模型倾向于"保守" |
| 物理不对：液体、碰撞、布料、手和物体的交互 | 模型学的是像素的统计规律，没有学到物理定律 |
| 物体凭空出现或消失、手指数量变化、文字乱码 | 时间一致性只靠 attention 维持，小物体占的 token 太少 |
| 纹理闪烁、边缘"游动" | 每一帧的高频细节都是"重新编出来"的，帧与帧之间对不上 |
| 时长短、几乎没有剪辑和叙事 | 序列长度受 attention $O(N^2)$ 的限制 |

## 本质

模型优化的目标是"看起来合理"，而不是"真实"。真实世界里随机、不完美的部分（传感器噪声、手抖、杂乱的背景、不完美的光线）恰恰被训练目标当成噪声去掉了。人眼对这类"过于完美"非常敏感，跟恐怖谷效应是一类现象。

## 目前的改进方向（只能缓解，不能根治）

- 后期加胶片颗粒、轻微手抖、降低饱和度
- 训练时降低 CFG 系数，或使用 CFG 蒸馏
- 用手机实拍、监控视频等"不精美"的数据微调
- 加入物理先验或 3D/世界模型（例如 Genie、Cosmos 方向）

## 生成的视频不会明显变糊原因

- **token 是多通道的连续向量**。一个 token 对应 4帧 × 16×16 像素 × 3 通道 = 3072 个原始数值，被压缩成 2×2×16 = 64 个浮点数，压缩比约 48 倍。
- **视频的冗余很大**。H.264/H.265 的压缩比常在 100–200 倍，画面依然清晰；VAE 的约 48 倍压缩比视频编码还温和。
- **VAE 解码器会"补"细节**。训练时用了感知损失（LPIPS）和 GAN 损失，解码器学会生成逼真的纹理。主流视频 VAE 的重建 PSNR 大约在 30–36 dB，肉眼接近原图。

## 视频生成容易出问题的地方

| 现象 | 原因 |
|---|---|
| 小字、文字乱码 | 一个 16×16 的格子里放不下笔画细节 |
| 远处的小脸、手指变形 | 物体只占很少几个 token |
| 细密纹理（头发、草地）发糊或闪烁 | 高频信息被压掉，帧与帧之间解码不一致 |
| 快速运动产生拖影 | 时间方向压缩 4 倍，4 帧合成一个 latent |

## 业界常见做法

1. **低分辨率生成 + 超分**：先生成 480p/720p，再用超分模型放大到 1080p 或 4K。大多数商用产品都是这个流程。
2. **加大 latent 通道数**：压缩倍率提高的同时增加通道数，保住信息量。例如 Wan2.2 的 VAE 用 4×16×16 压缩，配 48 通道。
3. **插帧**：先生成低帧率视频，再插帧到 24 或 60 fps。
4. **refiner 阶段**：在高分辨率上再做少量几步去噪，补充细节。
